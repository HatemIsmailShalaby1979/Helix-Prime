# C4–C8 Implementation Notes

This document is the implementation companion to `docs/HELIX_CODEX_EXECUTION_STATUS.md`.
It describes the contracts and safe operating rules, not a production claim.

## C4 — adapters

`engines/base_adapter.py` owns the universal boundary. A concrete adapter must
provide:

```python
class MyAdapter(EngineAdapter):
    engine_id = "..."
    capability_ids = ("...",)

    def compute(self, payload, sample_data_mode):
        return metrics, evidence_extras
```

The template method freezes the `TaskRequest`, checks tenant/client context,
scans secrets, validates classifications and routes only owned capabilities.
The result is an `AdapterOutcome`:

- canonical `TaskResult` for the control plane;
- legacy-compatible `EngineResult` for existing engine callers;
- `ComputationEvidence` with method, formulas, parameters, input/output
  fingerprints, assumptions and data mode.

A payload that requests `is_sample`, `use_sample`, `sample_data`, `demo_mode`,
`synthetic` or `data_mode=sample` is refused when `sample_data_mode=False`.
That is a hard boundary, not a warning.

Six adapters in `engines/adapters.py` call the real modules under each engine's
`src/` directory. They do not rewrite the numerical engines.

## C5 — control seam

`control_plane/control_seam.py` exposes `ControlSeam.run`. It preserves one
correlation id across all hops and records causation in the step chain.

When no compliance decision is supplied, the run ends at `awaiting_approval`.
When denied, it ends at `cancelled`. Only an explicit approved decision reaches
WFM recalculation.

The cockpit's `Control Plane` page is read-only for mutations by design: buttons
are disabled until an authenticated governed API path is connected. Operators
can inspect the queue and the full timeline/hash fields now; the UI does not
silently mutate approval state.

## C6 — GM activation

`organization/gm_activation.py` validates each remaining GM against:

1. runtime `RoleSpec` (owned engines, classifications, limits and KPIs);
2. YAML role catalog (capabilities and implementation metadata);
3. explicit C6 validation properties.

The fraud alias is explicit: runtime `fraud_revenue_gm` maps to YAML `fraud_gm`.
The activation report currently returns seven active roles and zero blocked.

## C7 — sibling events

Sibling services integrate through JSON only. The v1 envelope requires:

- event type and version;
- tenant, client and correlation IDs;
- data mode and classification;
- SHA-256 payload digest.

The four payload contracts are in `v1.py`; published schemas are generated by
`registry.py`. `boundary.py` scans for sibling imports and vendored source.

## C8 — self-hosted profile

`infra/docker/` contains a multi-stage image and Compose profile. SQLite is
mounted at `/data`; startup initializes schemas and verifies the ledger before
launching Streamlit. `config-files/acceleration.yaml` supports `auto`, `cuda`,
`directml` and `cpu` Ollama profiles. Acceleration is optional and never changes
deterministic engine evidence.

**Driver-level (SQL) tenant scoping is NOT implemented.** A `control_plane/tenancy.py`
module previously claimed to provide `TenantContext` and `TenantScopedStore` binding
`tenant_id`/`client_id` into SQL, but it was never referenced by any code path and was
removed on 2026-09-11. Tenant and client isolation is enforced at the policy seam in
`security/policy.py::authorize`, which denies cross-tenant requests before they reach
storage. Driver-level enforcement is deliberately deferred; if it is ever required it
belongs inside `Store` itself, not in a wrapper module.

`scripts/export_evidence_pack.py` reads the ledger without changing it and
returns exit code 2 if hash validation fails.
