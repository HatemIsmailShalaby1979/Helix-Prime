# Helix Codex Coding-Agent Prompt Pack

## Shared constitutional preamble

You are implementing Helix Codex under Constitution 000.

Before changing code, read:

- `00_CONSTITUTION.md`
- `MASTER_STORY.md`
- `GOVERNANCE/`
- `ROADMAP.md`
- `README.md`

Engineering philosophy:

- Truth is the authority.
- Identity precedes implementation.
- Governance precedes capability.
- Every decision requires an owner, assumptions, evidence, authority boundary, and outcome.
- Every memory requires provenance.
- Simulated, historical, and live data must remain visibly distinct.
- Sensitive actions must fail closed.
- Self-improvement may propose changes, but may not silently modify itself.
- Every change must be tested, explainable, reversible, and documented.
- Do not claim completion based on documentation alone.
- Do not introduce live credentials, paid infrastructure, or destructive migrations without explicit approval.
- Preserve unrelated user changes.
- Use `apply_patch` for edits.
- Run focused tests, full tests, governance checks, and `git diff --check`.
- Stop and report if evidence contradicts the requested plan.

## Prompt 2 — Secure credentials and the L&D integration

Audit the L&D integration and all credential-handling paths.

Requirements:

- Immediately invalidate or rotate any exposed L&D token.
- Search source, history, logs, fixtures, documentation, and generated files for credential leakage.
- Replace embedded tokens with a credential-free remote URL or public endpoint where appropriate.
- Use GitHub-managed secrets or environment-backed configuration for any private credential.
- Never place credentials in source code, URLs, fixtures, screenshots, or documentation.
- Fail closed when a required credential is missing.
- Add secret-scanning tests.
- Document the rotation and validation procedure without exposing secret values.

Do not print, commit, or reproduce any credential.

Verification:

- Run repository secret scanning.
- Confirm the old token is absent from the working tree and tracked history where feasible.
- Test missing-credential behavior.
- Confirm the L&D path works through the approved credential-management boundary.
- If GitHub secret configuration requires external approval, stop after preparing the exact required configuration and report the blocker.
